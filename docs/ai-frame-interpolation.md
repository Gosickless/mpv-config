# AI 补帧组件管理与测试说明

AI 补帧是独立功能，不属于画质预设。右键菜单有“AI补帧：关闭/开启”和“补帧组件：未安装/已安装/需要更新”。点击组件这一项始终打开同一个组件管理窗口。

## 安装窗口

首次打开仅显示信息，不自动下载：约2.63 GiB下载量、至少12 GiB可用空间要求和实际安装目录。点击“开始安装”才开始。窗口显示下载进度条、百分比与已下载/总量。

- 下载中可点“暂停下载”；暂停后点“继续下载”。已下载内容保留，支持HTTP断点续传；服务器不接受续传时会安全地重新下载当前文件。
- 校验和解压阶段显示“检查文件/正在安装”；这两步不提供暂停，窗口保持响应。
- 关闭未完成的安装窗口会先询问，确认后停止任务并保留下载内容。若正在解压，可能需要等当前步骤结束。
- 完成后窗口显示“AI补帧组件已安装”，按钮变为“返回播放器”，不再显示脚本路径或开发测试信息。
- 之后再点右键菜单中的组件项，直接显示已安装状态、安装位置和安装时间。不会重新下载。
- 已安装的旧组件与当前配置要求不匹配时，显示“需要更新”和“开始更新”，点击后才会下载；更新失败保留原安装。
- 已安装或需要更新时，可点击“卸载补帧组件”，确认后清理环境、模型、缓存和下载文件，保留播放器配置。卸载完成后可以重新安装；安装或卸载过程中不提供另一项操作。
- “查看详情”只提供组件版本和错误/日志位置，不再显示引导查看使用说明的文字。完整说明保存在本文件中。

“返回播放器”只关闭组件窗口，不会启动另一个mpv。安装完成后，在原来的播放窗口点击右键补帧开关即可：脚本会先检查组件，再为当前进程加载私有运行库，不修改系统环境。首次安装也无需专门的启动器；如果当前进程已经加载了不同版本的组件，则需关闭并重新打开当前播放器一次，避免在进程内混用运行库。首次为该规格视频准备模型可能需要等待，播放器显示“正在准备”；正常完成后显示“开启”。画质可选轻量、均衡和高画质；输出可选自动两倍或24–360之间的整数目标，按最接近的半倍档计算，例如23.976输入选择60时实际约59.940 fps。

暂停后手动删除下载文件属于可恢复的中断：删除当前`.part`后会从零重下当前包；删除之前已经检查完成的包或整个下载目录，当前任务可能报错，需要点击“重试安装”重新检查并补下载。不能保证正在运行的任务立即发现并修复所有外部删改。失败时保留可用的旧安装和播放器配置。

“AI 补帧已开启”在本次开启成功时提示一次，暂停恢复和拖动后不重复提示。启动、恢复和拖动后保留3秒缓冲；之后若音画误差连续3次（每次间隔0.5秒）超过250毫秒，会关闭补帧并恢复原画同步播放，提示降低帧率或画质。目标帧率不等于硬件实际处理能力，不再仅凭输出帧率数值判断已正常开启。

## 安装位置

安装目录默认 `%LOCALAPPDATA%\mpv-rife`。家里账号如果是Gosickless，对应 `C:\Users\Gosickless\AppData\Local\mpv-rife`。目录可由实际配置目录内 `script-opts\rife.conf` 的 `runtime_root=` 指定；留空使用默认。

## 已实现但尚未完成目标硬件验收

当前分支是实验实现，不是正式发布：

- Python3.13.9、VapourSynthR79、vs-mlrt15.16（CUDA13.2/TensorRT10.16.0）固定下载源和SHA256，环境独立，不改系统Python/PATH。
- 下载管理窗口、真实暂停/续传、校验、安装锁、版本化环境和失败不覆盖旧安装。成功、失败或取消后清理本次解压目录；已下载文件保留用于续传或重装。旧版本组件提供更新入口。
- 独立补帧开关、模型准备进程、旧文件任务作废、仅操作自己的 `@mpv_rife` 滤镜；已有其他vf时拒绝盲目组合。
- 固定下载RIFE4.25的轻量、均衡和高画质模型；使用内部补边实现保持原分辨率，返回10位输出。接受偶数尺寸最高3840×2160、1–30fps逐行输入。
- 按运行库、GPU及驱动、尺寸和模型隔离引擎缓存；准备与读取共享跨进程锁，取得真实推理帧后才原子发布。取消准备留下的工作目录在下次获取同一锁后清理。
- 准备阶段复用缓存时取得真实推理帧；若旧缓存加载或推理失败，只清理对应缓存并重新准备一次，仍失败则停止并提示。没有完成标记的残留目录也可重新准备，不影响其他规格缓存。

已在RTX5070验证不预设组件环境变量的当前进程直接启用、全新安装、1080p SDR推理、暂停、拖动、倍速切换和关闭。CLANNAD第6集实测：增加帧并发、两路推理和CUDA图后，均衡约59.940 fps短测保持音画同步；高画质自动两倍约47.952 fps短测保持同步。均衡120档、高画质60档及轻量120档在该片源上不能维持实时处理，已验证自动恢复原画并重新同步。启动期仍有掉帧；无窗口短测不代表屏幕呈现帧率或整部片验收。仍待验证1440p/4K实时性能、显存释放、长片/切集/片尾、HDR10画质/静态元数据/实显。

轻量和高画质4.25模型在该片源的FP16推理中会产生非有限RGB值，表现为整帧绿闪；这两个模型现改用保留FP32数值范围的TF32计算，均衡继续使用FP16。准备和播放共用同一后端设置，变更精度的模型使用新缓存键，避免重用旧引擎；首次开启需重新准备。实际视频逐帧抽查已验证本次绿闪消失，TF32不保证所有目标档位都能实时运行。

## HDR10与输入限制

HDR10候选链保留浮点PQ编码RGB后回到10位YUV。按用户选择，默认 `experimental_hdr=yes`，开启补帧时允许HDR10进入实验处理链；需要关闭时可在 `script-opts\rife.conf` 改为 `no`。杜比视界与HLG暂不处理，HDR画质与静态元数据仍未完成验收。

CPU测试确认标准mpv0.42.0经过不含RIFE的颜色往返链后，PQ、BT.2020、矩阵及10位标记可保留；不代表真实AI插帧后的亮度/颜色和HDR静态元数据已验证。帧时长检查不能仅靠平均帧率证明所有片源是CFR，真实VFR及片尾仍待测试。

## 运行环境与维护

- `runtime/`：版本化Python、VS、推理库、上游许可；`active.json`记录当前版本。
- `cache/`：按规格和GPU隔离的本机TensorRT引擎、锁和完成记录，不应跨机器直接复制。
- 已完成的引擎及附属编译缓存合计超过2 GiB时，在模型准备成功后按最近成功使用时间清理到1.5 GiB。跨运行库版本共同计量；旧缓存没有使用记录时以完成记录的时间排序。当前刚准备的引擎、正在准备的引擎和播放期间持有使用锁的引擎会跳过，因此占用期间可暂时超限。下载包、运行库、模型和未完成的准备目录不计入此上限。
- `downloads/`：已校验下载包和可继续的`.part`；`staging/`：临时解包目录。
- `jobs/`：每次安装独立的进度、控制标记和日志，避免旧进度污染新窗口。
- `logs/prepare-*.jsonl`及配套`.stderr`：每次模型准备的结果和推理库日志（包含正常警告），统一生成到`logs/`。下次启动mpv时后台清理这些日志，兼容清理旧版留在组件根目录的同名日志；有其他播放器正在准备、安装或卸载时跳过，留到下次启动。不会清理引擎缓存、运行库、下载包或其他文件。分享日志前检查本机路径等私有信息。

关闭补帧不影响画质预设、音量和字幕。新进程默认关闭。运行库可能驻留进程，退出mpv是彻底清理加载库的边界；不能仅凭菜单“关闭”宣称显存完全释放。

卸载通过组件管理窗口执行，会同时清理专用目录中的旧版环境。应先关闭使用该环境的播放器与准备进程；若检测到占用，会拒绝卸载并提示重试，不强制退出播放器。卸载前校验目录范围和所有条目，遇到链接目录或不属于组件的顶层文件时停止，避免误删；需要保留的日志应先自行备份。更新时仍保留旧版环境，不自动回收。

## 开发测试记录

- `python -B tests/test_rife_policy.py`：输入范围和HDR实验门禁。
- `python -B tests/test_rife_download.py`：本地HTTP真实暂停/续传、服务器忽略Range时的安全重下和最终SHA256；不下载上游包。
- `python -B tests/test_rife_manager.py`：首次查看不触发安装、中文路径的已安装记录正确打开状态页；使用隔离夹具，不表示真正安装过完整环境。
- `python -B tests/test_rife_engine_cache.py`：跨进程等待、原子发布、失败重试、取消恢复与GPU/模型隔离。
- `python -B tests/test_rife_staging.py`：清理范围保护、真实安装解压失败时清理和保留旧版本/下载包。
- `python -B tests/test_rife_uninstall.py`：隔离目录卸载、配置保留、确认要求、安装锁与未知文件保护。
- `tests/test_rife_activation.py`：设置`RIFE_TEST_MPV`和`RIFE_TEST_ROOT`后，用真实播放器验证同进程加载、中文环境、重复启用和版本冲突保护；未提供本机组件时跳过。
- `tests/test_rife_playback.py`：设置`RIFE_TEST_MPV`后执行真实Lua控制器，验证暂停/拖动不重复提示、持续不同步时关闭滤镜及恢复期间的缓冲保护。
- `tests/test_rife_prepare_logs.py`：验证启动清理、正在准备时跳过、精确文件名范围和其他数据保护；使用隔离目录，不清理实际组件目录。
- `tests/test_rife_video.py`：额外设置`RIFE_TEST_VIDEO`为本机1080p SDR测试片源，验证真实推理输出的非有限RGB值、均衡60档同步及过载恢复；无窗口测试不写入播放进度，不下载依赖，临时脚本和日志自动清理。
- Lua控制、PowerShell解析及上述1080p GPU播放流程已验证；剩余硬件和HDR项目如上。

依赖采用Python、VapourSynth、AmusementClub/vs-mlrt官方发布资产；上游模型/推理库许可随包提供。源代码中的 `launch.ps1` 保留为高级手动入口；普通用户直接在当前播放器开启补帧即可。Windows同进程加载需要启用了LuaJIT/FFI的mpv构建，当前本机开发构建已经实测通过。
