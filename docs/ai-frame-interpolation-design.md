# AI 插帧扩展设计（待实现）

本文件是设计，不表示补帧功能已经可用。现有画质预设保持独立。未经后续明确指示，不提交、不推送、不创建分支，不下载运行环境。

## 1. 已确定的目标

- Windows x64、NVIDIA RTX；主要验收设备为用户家里的桌面 RTX 5070。
- 独立右键菜单“AI 补帧”；开启/关闭合并成一个菜单项，不加入画质预设。
- 第一版目标包含 SDR、HDR10、1080p、2560×1440、3840×2160；固定两倍帧率，保持原始分辨率，不静默降采样。
- 23.976→47.952、24→48、25→50、30→60。高于 30 fps 的输入先作为压力测试，不承诺第一版启用；支持范围以最终验收为准。
- 杜比视界暂不处理；HDR10+、HLG、交错视频、可变帧率和动态尺寸输入不纳入首版验收。无法确认输入条件时提示原因并维持原帧播放，不能静默宣称已补帧。
- 不改变字幕、音量、播放列表和历史；不把 HDR 转为 SDR 冒充 HDR 补帧。
- 关闭时不加载补帧滤镜、不启动 Python/推理进程、不自动下载或编译；保留轻量 Lua 事件监听。

## 2. 菜单与交互

```text
AI 补帧
  补帧：关闭                  # 同一项切换为开启/准备中/不可用
  安装／更新运行环境……
  取消当前准备任务            # 仅下载/生成引擎时可用
  查看运行信息
  打开运行环境目录
  卸载运行环境……
```

未安装时点击开关：展示检测到的显卡、明确的下载/解压体积、保存目录和运行要求；用户确认后才下载。不能以点击一次开关视为同意不明体积的下载。安装后继续执行本次开启请求，用户取消则保持关闭。

菜单标题通过 menu-data 写入实际文字，不使用 menu.conf 不支持的属性展开。只修改本扩展所属菜单项，避免与 quality_presets.lua 的去色带菜单观察器反复覆盖。更新前比较内容，变化时才写回。

运行信息显示：用户请求状态、实际滤镜状态、片源尺寸/帧率/SDR或HDR10、模型标识、后端版本、实际硬件、引擎缓存命中、跳过/失败原因。帧率和模型运行信息必须来源于实际属性或测量，不用目标值冒充实测值。

## 3. 交付形态和目录

配置仓库只放控制代码、小型脚本与依赖清单。运行环境单独安装，不进入 Git。保持已有文件位置，仅新增以下候选路径：

```text
scripts/rife.lua                    # 生命周期、菜单和 mpv 滤镜开关
script-opts/rife.conf               # 用户选项，不存本机引擎或凭据
rife/interpolate.vpy                # 标准 VapourSynth 接入
rife/runtime-lock.json             # 经过验证的精确版本、下载源、大小、哈希、许可
rife/helper/                       # 安装、探测、引擎准备辅助程序
docs/ai-frame-interpolation.md      # 实现完成后的用户说明
```

默认环境根目录使用 Windows LocalAppData 的实际值，不硬编码用户名：

```text
%LOCALAPPDATA%/mpv-rife/
  runtime/<runtime-id>/             # 已发布、校验完整的不可变依赖环境
  staging/<job-id>/                 # 下载和解压临时目录
  cache/<runtime-id>/<gpu-key>/      # 本机 TensorRT 引擎
  logs/                            # 有大小/数量限制的诊断日志
  state.json                       # 激活版本和安装状态
```

例如当前用户为 C:/Users/haochen.xu/AppData/Local/mpv-rife；家里按实际账号展开。配置仓库中的运行路径保持可移植。首版不同时实现第二套便携安装逻辑。

辅助程序不能依赖尚未下载的 Python 才能安装 Python；Windows 自带 PowerShell/.NET 可作为启动安装器的候选，进程隐藏启动，状态回传播放器。大环境不修改系统 PATH、注册表或系统 Python，只为本次启动构造进程环境。

## 4. 依赖与播放器选择

核心链：mpv → VapourSynth → vs-mlrt → TensorRT/RIFE → mpv GPU 渲染。

- 先以已下载并验证具备 VapourSynth 的官方 mpv 0.42.0 full 构建为基准。
- 原 0.41.0-923-g7b8915bc1 的源码不能证明二进制启用了所有功能；拿到家里的原始 exe 后检测滤镜与实际运行库加载，通过后才列为兼容。
- 优先标准接口，不使用 Tigerest 的 eof-aware 参数，也不复制后删除其参数冒充兼容。
- Python、VapourSynth、vs-mlrt、TensorRT、模型和驱动要求作为一组锁定验证；RTX 5070 必须满足 Blackwell 支持。精确版本和模型尚未选定，禁止先写“已支持”。
- 私有 VSSCRIPT_PATH 与 DLL 搜索路径在安装探测时验证。若 Windows 原生 DLL 加载必须在 mpv 启动前配置，则提供配套启动器并明确提示首次重启；不能承诺双击任意 exe 后无需重启就能首次启用。
- 不用官方不支持的特殊接口；若标准接口无法可靠处理片尾/跳转/HDR，则形成具体阻断报告，再讨论补丁路线。

## 5. 开关状态与资源生命周期

区分 requested（用户希望开启）与 active（滤镜确实运行）：

```text
未安装 → 等待确认 → 下载 → 校验/安装 → 就绪（关闭）
就绪（关闭） → 输入/硬件检查 → 引擎准备 → 开启
开启 → 关闭/输入不支持/运行错误 → 清理 → 关闭或错误
```

每个加载文件与后台任务使用递增 generation id。旧影片的引擎准备结果不得挂到新影片，取消/关闭后的迟到回调不得重新开启。

开启时只通过专属标签（例如 @mpv_rife）增删自己的 vf，不覆盖整个 vf。不清除其他裁剪、反交错、用户滤镜，也不触碰 glsl-shaders。遇到无法判断的既有滤镜组合先提示不支持，不盲目插到未知位置。

现有 quality_presets.lua 只管理画质属性；目前不写 vf，两个功能独立。同一个 GPU 上共同运行会争用资源，不能保证所有重型预设与4K补帧组合都实时。

同进程切集保留 requested，但每个文件重新检查并重建 active；不支持的新片源原帧播放并说明原因。新进程默认关闭，不持久化开启状态。

关闭时取消准备任务、移除专属滤镜、清理 worker/VS session，恢复本扩展临时改变且仍归其所有的属性；不回滚用户后来主动修改的值。引擎文件可保留。显存释放和辅助进程退出必须实测；不能把菜单变成“关闭”视为释放成功。

失败时每个文件最多一次有界恢复，避免循环加载失败；保留当前文件、位置和暂停状态。需要重载才能恢复时显示原因，不静默反复 seek。

## 6. HDR10 处理设计与验证门槛

HDR10 是首版验收目标，不是现有能力。先针对 PQ/ST2084、BT.2020 容器、10位输入，杜比视界明确跳过。

候选链：解码原始高位深 YUV → 正确范围/矩阵变换 → 明确的模型输入域 → RIFE → 逆变换 → 高精度输出 → mpv HDR 输出或色调映射。

必须通过实验决定模型在何种域工作：直接 PQ RGB、线性光或可逆的压缩映射不能凭名称选择。不能假设 SDR 训练模型对 HDR 适用，也不能声称可逆数值变换可保证模型预测无误。使用 HDR 测试片检查亮部、近黑、饱和色与运动边界。选择后记录算法和限制。

不把输入降为8位；颜色转换使用浮点/足够精度，返回视频保持至少10位有效精度。支持的具体 VS/输出格式以验证为准。

原始帧与生成帧均需正确的矩阵、原色、传递函数、范围、色度位置和时间戳。静态母版信息、MaxCLL/MaxFALL 需要核实从 mpv 到 VS 再到输出是否完整保留；标准接口未暴露的数据不能靠猜测重建，也不能仅写几个帧属性就宣称 GPU 输出收到相应元数据。

若接口不能无损保留必要信息，HDR 模式不得标为可用；可以报告阻断，但不能未经用户同意把 HDR 移出首版目标或偷偷转成 SDR。

## 7. 性能与帧率策略

- 两倍严格保留有理帧率，例如24000/1001→48000/1001，不擅自变成48/60。
- 常见恒定帧率视频为首版输入；元数据不足以确认时采用探测而非只读一个平均帧率。
- 先在5070上测1080p、1440p、4K的24→48及30→60；4K60→120列为压力场景，不提前承诺。
- 统计整体播放掉帧、推理时间、GPU/CPU/显存和音画偏差；目标帧率、实际生成速度、屏幕呈现频率分开记录。
- 首次引擎生成与热缓存播放分别测试，不把编译等待计作稳态速度。
- 片源尺寸/模型/精度/后端/GPU/相关兼容版本作为引擎缓存键；检查完整性并原子发布，不跨机器复制缓存宣称通用。
- 性能不足提示用户关闭或换明确标识的轻模型，不静默降低分辨率、替换算法或关闭用户 shader。
- 帧率与屏幕刷新率不整除可能产生显示节奏问题，须解释，不能以屏幕120/144Hz推断模型需要补到该帧率。

## 8. 安装、更新和卸载

安装前检查系统、GPU/驱动、磁盘空间和联网状态。依赖来自固定可信上游资产，下载清单包含实际大小、SHA-256、许可。现有开发环境里可用的代理地址不能写进用户配置。

支持进度、取消、断点恢复或干净重试；解压限制在staging内，防止路径越界。全部校验与运行探测通过才切换active版本。失败保留旧版本，禁止显示假成功。

多个mpv实例共享安装锁和引擎准备锁；缓存发布原子化，使用中的环境不立即删除。卸载前展示将删除的环境/缓存范围并确认，不删除mpv配置、视频和无关目录。

## 9. 分阶段实施（均先本地，不提交/推送）

1. 可行性样机：独立测试目录，锁定支持5070的依赖；验证标准0.42.0的VS输入、RIFE两倍、跳转和片尾；同时验证HDR信息通道。
2. HDR10与性能：选择并验证色彩处理方法，家中5070测SDR/HDR10、1440p/4K、冷启动/热缓存。
3. 可选扩展交付：完成按需安装、单项开关、generation取消、资源释放和状态菜单。
4. 整合现有配置：保留目录与现有快捷键，测试与11档画质、thumbfast、字幕、保存进度的共同运行；再更新用户README。

任一阶段失败应记录具体能力缺口，不直接进入大规模下载/配置改写掩盖问题。当前Intel Iris Xe电脑只可验证部分控制/安装流程，不能据此验收5070的TensorRT或HDR实显效果。

## 10. 验收清单

- 未安装/关闭：不启动后台推理进程，无补帧vf，无主动联网；对比原配置稳态CPU/GPU/显存和掉帧。
- 开关：关闭释放资源，连点/准备中取消/后台任务迟到不重新开启；不破坏其他vf。
- 文件生命周期：精确/关键帧seek、暂停恢复、倍速、切集、结束、EOF前一帧、短片、损坏片、反复开关、两个窗口。
- 画质：1080p/1440p/4K，23.976/24/25/29.97/30，SDR/HDR10；重复帧动画、切镜头、遮挡和细线。
- HDR：10位梯度、近黑、高光、BT.2020色彩及HDR10静态信息；HDR屏输出和SDR屏映射；不支持格式明确跳过。
- 整合：11档画质来回切换不移除补帧，补帧开关不改画质；字幕/OSD不被错误送入模型；缩略图进程不加载补帧链。
- 数据：进度、音量、字幕偏好、播放列表保持；运行路径/缓存/日志不进入Git。
- 安装：下载中断、校验失败、空间不足、权限不足、代理不可用、并发安装、旧缓存失效和卸载取消。
